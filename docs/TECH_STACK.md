# 技术选型文档 v1.0（技术总监定稿）
> 议题：本游戏（2D 俯视塔防，多单位移动+双向战斗+4 种族技能）用什么技术栈最合适
> 纪律：每项=约束→方案→验证→风险；性能有预算；架构决策记录原因（ADR）

## 0. 结论先行
- **游戏本体：Godot 4.5（GDScript，热路径可加 C#）**——现有原型即此栈，M1/S1 已验证
- **Python：只做工具链**（AI 概念出图 / 平衡仿真 / 数据分析 / 生成关卡与波次 JSON），**禁止进入游戏运行时**
- 不换引擎：换引擎=重写，违反重构纪律（"先这么写后面再重构"=重写，禁止）

## 1. 需求约束（本项目的硬性条件）
| 约束 | 值 |
| --- | --- |
| 类型 | 2D 俯视塔防；单位可移动、自动攻击、怪物反击 |
| 同屏规模 | 己方 ≤30 单位 + 敌方 ≤60（波次） + 子弹/粒子 ≤60 = ≤150 实体 |
| 玩法核心 | 移动拦截 + 双向战斗 + 科技进化 + 技能 CD + 四族差异化 |
| 发布 | Steam（Windows 为主） |
| 预算 | 业余时间 10h/周 单人团队；零引擎许可费 |
| 迭代 | 每日原型验证，热重载优先 |

## 3. ADR 记录（每项=约束→决策→原因→风险）
- ADR-001 引擎 = Godot 4.5。原因：CanvasItem 2D 批处理天然适配 ≤150 实体；热重载支撑每日迭代；Steam 导出零费用；导出包小。替代方案（Unity/Unreal/自研）已评估拒绝。风险：Godot 生态比 Unity 小（社区资产生态），但本项目全脚本自绘，不依赖商店资产。
- ADR-002 语言 = GDScript 主，C# 热路径可选。原因：现有实现全 GDScript 且冒烟通过；GDScript 迭代最快。风险：极热路径（每帧超 1 万次运算）可降级 C# 或 C++ GDExtension——当前规模不需要，预留接口即可。
- ADR-003 Python = 纯工具链（禁止进运行时）。原因：平衡仿真蒙特卡洛/数据分析用 Python 科学栈效率高；生成 JSON 配置（波次表/数值表）供 Godot 读，避免双写。风险：若开发者贪快把逻辑写进 Python → 运行时性能与打包双失败，一票否决。
- ADR-004 数据契约 = JSON 单向（Python 生成 → Godot JSON.parse）。原因：数值/波次/种族表由数据分析师与设计产出 Python 侧，引擎侧只读。风险：字段变更需双向同步——由变更单控制（CO-001 已规范）。

## 4. 性能预算（超标即阻断，技术总监门禁项）
- 帧时间 ≤16.6ms（60fps）；同屏实体 ≤150（己方 30+敌方 60+投射物 60）
- 绘制：CanvasItem 自绘合并批（unit/_draw 已按此设计）；禁止每帧新建材质/纹理
- 内存：运行时纹理总量 ≤256MB（AI 概念图只在设计期参考，不打包进运行时）
- 加载：主场景 ≤2s；模型/关卡配置 JSON ≤500KB
- 粒子：单单位粒子预算 ≤30 点/帧（AI 出图视觉可部分等效落引擎，见 ART_GUIDE §1）

## 5. 风险登记（新增，并入 RISK_REGISTER.md）
- R-ENG1（低/中）：150 实体同屏 2D 绘制优化（按需隐藏、区域剔除）——S2/S3 加压测试验证
- R-ENG2（低）：C# 热路径引入时机（预留接口，当前不需要）
- R-ENG3（已消除）：误用 Python 写运行时——ADR-003 一票否决 + 代码评审

- 与现有实现一致性：100%（原型即 Godot 栈，无迁移）
