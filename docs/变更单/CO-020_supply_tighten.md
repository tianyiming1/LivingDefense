# 变更单 CO-020：人族补给收紧（经营压力）

- **状态**：已实施
- **日期**：2026-09-03
- **WP**：WP-ECO1（`docs/派工_WP_可玩性丰富度.md`）
- **依据**：`docs/数值_人族铁皮补给_极限检查_2026-09-03.md`
- **生效版本**：config CO-020（仅补给产速/库存/开局三常量）
- **批准**：派工 WP-ECO1 必做切片

## 为什么变

极限检查结论：补给线可闭合，但**满配 2 站×多农产速偏高**，后期几乎不构成抉择；开局不建站仍应在 1–2 次进化后卡死（设计意图保留）。本单只收紧补给杠杆，不改铁皮减伤、单位表、波次公式。

**目标（DoD）**

1. 开局不建站 → 几次高端进化/建造后补给触底（会卡）。
2. 满产仍受 `DEPOT_STOCK_MAX` + `MAX_SUPPLY` 双闸，清波补满后仍要管农/管站。

## 常量表（生效）

| 常量 | 旧 | 新 | 理由 |
| --- | ---: | ---: | --- |
| `FARMER_SUPPLY_AMOUNT` | 3 | **2** | 单农产速 −33%；拉长「要不要再开农/再建站」窗口 |
| `DEPOT_STOCK_MAX` | 30 | **24** | 每波清波补满后库存 −20%；满产后仍要管农，避免后期补给无抉择 |
| `START_SUPPLY` | 36 | **32** | 略逼早建站；火枪双买（−16）后余量更紧，不建站更早触底 |

**不改（本单）**

| 项 | 值 | 说明 |
| --- | --- | --- |
| `MAX_SUPPLY` | 48 | 玩家补给上限保持 |
| `FARMER_SUPPLY_INTERVAL` | 3.0 | 产间隔不动，只降单次产量 |
| `FARMER_MAX` / `DEPOT_MAX` / `DEPOT_SLOTS` | 4 / 3 / 2 | 编制上限不动 |
| `HUMAN_UNITS[*].supply_cost` | 既有 | 消耗闸门不动；本单只动供给侧 |
| `armor_melee` 等铁皮系数 | — | 极限检查「若试玩仍糊再压」→ 另单 |

## 纸面极限（收紧后）

| 情景 | 估算 |
| --- | --- |
| 开局补给 | **32** / 48 |
| 波 1 典型：2 火枪直购 | −16 → 余 **16**（旧 20） |
| 火枪进化 −8；迫击进化再 −18 | 不产则易触底（意图保留） |
| 单站 2 农满产 | 每 3s **+4**（旧 +6）；站库存 **24** ≈ 6 拍清空（约 18s 满速） |
| 理论满编 2 站×2 农 | 每 3s 最高 +8，仍受站库存 24×站数与玩家上限 48 双重闸 |
| 对比旧满产 | 旧约每 3s +12 @ 库存 30 → 新更紧，清波后仍要抉择 |
