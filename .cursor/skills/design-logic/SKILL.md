# Design Logic（设计基本逻辑）— 本项目必读

创意负责发散，逻辑负责保证**不矛盾、算得平、可验证、敢署名**。
任何设计/布局/镜头/数值决定，过完五关才能拍板或宣称「已修好」。

## 基本逻辑五关（任何产出必过）

1. **定义关（同一律）**：关键概念全文同义；禁止偷换口径（例：「战场 16:9」≠「窗口随便拉伸后看起来差不多」；`VIEW_SIZE` / `HUD_BOTTOM_PX` 唯一口径见 `Config`）。
2. **自洽关（矛盾律）**：机制无自相矛盾；规则优先级明确；**账能算平**。例：禁止同时成立「底栏常驻叠在路径上」∧「路径完全可见可点」。
3. **反例关**：宣称「好玩/平衡/已修好」前先找反例。已证伪方案（如：本机 `gl_compatibility` 下 SubViewport 战场白屏）禁止无新证据复用。
4. **可验证关**：每个断言有可检查形式——精确值/矩形/时机/命令输出；禁止「更清楚/比例正常」形容词验收。
5. **确定度关**：结论标 **事实 / 假设 / 口味**。口味不能当工程依据；假设写明待什么证据证伪。

## 常见谬误（见到就标红）

- 相关当因果；确认偏误；事后归因；伪精确；目标置换。
- **以先后为因果**：改完 HUD 后「好像好了」≠ 根因已消——要安全带断言或截图证据。
- **偷换论题**：用户说「挡路」却只回「压缩了一点透明度」。

## 设计/UI 文档写法

- 改一条扫冲突（改底栏高度 → 重算镜头 offset / 安全带 / 路径可见区）。
- 数值与布局常量单一来源：`scripts/config.gd`。
- 预留「为什么」；变更走变更单。
