# game-studio-pipeline v2（完整工作室角色）

对齐 game-studio agent 预设的 **18 角色 × 5 条线**，按"议题激活 + 依赖顺序"编排多 agent。

## 角色注册表（= 预设 18 角色）
- 决策层：制作人 · 创意总监
- 设计线：主设计师 · 数值设计师 · 关卡设计师 · 叙事设计师
- 工程线：技术总监 · 玩法工程师 · 管线工具工程师 · 技术美术
- 美术线：美术总监 · 概念美术 · UI·UX · 音频设计师
- 质量线：QA 主管 · QA 测试员
- 数据/发行线：数据分析师 · 社区与商店经理

## 阶段与依赖（有依赖串行，无依赖并行）
```
0 立项：制作人开单（scope + 里程碑目标）
1 设计冻结（串行·先行）：设计线按议题激活 1..N 个设计师 + design-logic 五关
   → CO 变更单 = 唯一契约
2 并行执行线（只依赖①）：工程线 ∥ 美术线 ∥ 音频 ∥ 数据 ∥ 发行（按议题激活）
   · 工程线：实现 config.gd/脚本 + headless 冒烟
   · 美术线：ART_Brief + 生成 prompt + visual-art-qa 清单
   · 音频线：音效/BGM 需求单
3 QA/门禁收口（串行）：契约闭合 + 冒烟 + 对照 M0-M5 exit criteria → pass/needs-user/fail
```

## 议题激活规则（默认不全员上，省 token）
任务里提到 数值/平衡 → 激活数据线；美术/UI/精灵/图标 → 美术线；
音 → 音频；代码/实现/技能/进化 → 工程线；上架/发行 → 发行线；QA 永远收口。
**大里程碑/全流程**：调用加 fullStudio=true → 决策层+全线参与。

## 调用

> （全流程时）…：任务="达成 M3 门禁"，fullStudio=true

## 契约与纪律（对齐预设）
- CO 变更单 = 唯一事实源；数值单一来源 config.gd；变更走 CO；文档与实现一致
- 含糊/需拍板项 → blockers 汇总交用户，不假装通过
- 门禁不过不进下一阶段；设计先行单跑确认（省 token）→ 再跑并行线 → QA 收口
